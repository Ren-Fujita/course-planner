# 履修登録シミュレーター PWA 1.1.0

2026年10月11日更新の「履修登録シミュレーター.html」を元にしたPWA版です。時間割、履修履歴、卒業要件の確認、科目編集、JSONの書き出し・読み込みを保持しています。

## 1.1.0の変更

- 時間割の下に「オンデマンド」欄を追加しました。「授業を選ぶ」で、表示年度・学期・年次に合う授業を選べます。授業名から詳細の変更、科目編集、修得済みへの変更、削除ができます。固定の曜日・時限の枠は使いません。
- 「必修を自動追加」を初期状態でオンにしました。履修計画を開いたとき、表示年度の年次に合う全員必修と、選択中の目標プログラムの必修を追加します。登録済み・修得済みの科目を重複追加せず、既存の年度・クラス・履修状態を保持します。
- 複数クラスがある必修は、全クラスに共通する曜限を仮置きします。「クラス未選択」と表示される科目を開き、所属する開講クラスを選んで保存してください。共通の曜限がない科目は「この期間の科目」から開けます。
- 先修条件・単位上限・既存授業との重複で自動追加できない必修は、画面に理由を表示します。科目や開講情報を確認・修正できます。
- 削除した必修は再起動後も自動で戻りません。「削除した必修を戻す」で、その年度の自動追加対象に戻せます。自動追加をオフにしても、すでに配置した科目は残ります。

## GitHubで公開済みの1.0.0から更新する

同じリポジトリの同じ場所へ、このZIPの `index.html`、`manifest.webmanifest`、`pwa.js`、`pwa.css`、`sw.js`、`icons/` をまとめてアップロードし、1回のコミットで上書きします。`source/`は公開に不要です。配信が更新されたらアプリをオンラインで開き、「アプリ」→「更新を確認」→「更新して再起動」を押します。

同じURL・同じ端末の保存領域で使えば、既存の計画・修得履歴を引き継ぎます。旧版からの更新時は、自動追加の対象になる未登録の必修も配置されます。JSONの保存形式は引き続き `version: 1` です。

## 使い始める

1. このフォルダをHTTPSで配信するサーバーに置きます。GitHub Pagesでも利用できます。
2. 公開URLを開き、右上の「アプリ」で「オフラインの準備ができました」と表示されるまで待ちます。
3. iPhone・iPadはSafariの共有メニューから「ホーム画面に追加」を選びます。「Webアプリとして開く」が表示されたらオンにします。Android・パソコンはChrome・Edgeのメニューからインストールできます。
4. ホーム画面やアプリ一覧から起動します。初回保存後は、オフラインで再起動・編集・保存できます。公式資料への外部リンクには通信が必要です。

`index.html`をダブルクリックして開く方法では、PWAのインストールやオフライン起動の設定はできません。ZIPをスマートフォンへコピーするだけでもインストールはできません。

## GitHub Pagesで公開する場合

リポジトリ直下へ以下を配置し、Settings → Pagesから配置したブランチと `/(root)` を公開元に設定します。`index.html`が公開元の直下になるようにしてください。

```text
index.html
manifest.webmanifest
sw.js
pwa.js
pwa.css
icons/
```

`source/`とREADMEは公開に不要です。サイトのルートでも、`https://example.com/course-planner/`のようなサブフォルダでも動きます。

## 以前の計画を移す

元のHTMLを、これまで使っていたブラウザで開き「書き出す」でJSONを保存します。PWA版を開いて「読み込む」からそのJSONを選び、確認画面で実行してください。インストールしたアプリ内にも計画があることを確認します。iPhone・iPadでは、必要に応じてインストール後のアプリでもJSONを読み込んでください。

保存キー `shunan-course-planner-2026-v1` とJSONの `version: 1` は維持しています。同じブラウザの同じ配信元では従来データを利用できますが、元のローカルHTMLから別URLへ移す場合などは自動移行されません。自動のクラウド同期は行いません。アプリ削除・ブラウザのデータ消去・OSの保存領域整理に備え、定期的にJSONを書き出してください。

## 更新する

公開ファイルを差し替えたあと、オンラインで開くと更新を確認します。右上の「アプリ」→「更新を確認」でも確認できます。新しいファイルの保存が完了すると「更新して再起動」が表示されます。編集中の内容を保存してから押してください。保存済みの計画・履修履歴は更新後も保持されます。

新しいService Workerは初回だけ自動で有効になります。更新版は、利用者が再起動を選ぶか、古い版を使用するすべてのタブ・アプリが閉じられるまで待機します。同じ配信元にある別アプリのキャッシュを削除しません。

## ローカルで確認する

Pythonがあるパソコンでは、このフォルダで次を実行し `http://localhost:8000/` を開きます。localhostはPWAの開発確認に利用できます。同じLAN内のIPアドレスを使った通常のHTTP接続では、スマートフォンでPWAの確認はできません。

```text
python -m http.server 8000 --bind 127.0.0.1
```

## ソースから再生成する

Python 3.9以降とNode.js 20以降を使用します。ビルドと付属テストに追加パッケージは不要です。

```text
cd source
python build.py
node --test tests/engine.test.cjs tests/ui.test.cjs tests/snapshots.test.cjs tests/persistence.test.cjs tests/render-cache.test.cjs tests/build.test.cjs tests/planning-additions.test.cjs
```

アプリ本体は`source/src/`、PWAの追加部分は`source/src/pwa/`です。生成済みファイルへの直接編集は次のビルドで置き換わります。ビルド時に配信ファイルからキャッシュの識別子を自動生成するため、ファイルを変更すると更新版として認識されます。更新時は配信ファイルを一式差し替え、`sw.js`を最後に配置するか、一括デプロイしてください。

元の単独HTMLは `python build.py --output 任意の保存先.html` でも生成できます。
